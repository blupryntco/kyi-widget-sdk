Integration guide

Add the KYI widget to your platform: one endpoint on your backend and one function call on your frontend.

1. Get your credentials

Contact your Bluprynt representative to set up a partner integration. You will receive:

  • Partner ID, used as the token's issuer.
  • SECRET_KEY, used to sign access tokens. Store it like any other server secret, for example in an environment variable, and never ship it to the browser.

Bluprynt also needs from you:

  • The origins where you'll embed the widget, for example https://app.example.com and https://staging.example.com. Include every environment you test in, including local development such as http://localhost:3000. Bluprynt adds these to its CSP and CORS policies.
The widget only loads on allowlisted origins. On any other origin the browser blocks it, and you'll see an empty frame or a CSP error in the console. If that happens, check that the exact origin (scheme, host and port) is on your list.

2. Install the SDK

npm install @bluprynt/kyi-widget-sdk

The package has two entry points:

  • @bluprynt/kyi-widget-sdk for the browser: opens the widget.
  • @bluprynt/kyi-widget-sdk/server for Node.js 18+: generates access tokens.

3. Generate an access token on your backend

Add an endpoint that your frontend calls before opening the widget. It generates a short-lived token for the logged-in issuer.

import { generateToken } from '@bluprynt/kyi-widget-sdk/server'

app.post('/api/kyi/token', requireLogin, async (req, res) => {
  const accessToken = await generateToken({
    issuer: 'your-partner-id',
    secretKey: process.env.BLUPRYNT_SECRET_KEY,
    userId: req.session.user.id,
    expiresIn: 3600,
  })

  res.json({ accessToken })
})

Choosing a user ID

The userId is the only thing that identifies an issuer to Bluprynt, and Bluprynt trusts it as-is. Everything the issuer does in the widget (KYB, verified wallets, their on-chain identity) is attached to it. The ID you use must be:

  • Stable. The same issuer always gets the same ID. Don't use an email address or username that can change.
  • Unique and never reused. One ID per issuer. Don't give a deleted account's ID to a new user, and don't share one ID between issuers.
  • Internal. Use your database's primary key or a similar ID that users can't choose or edit.
Take the user ID from your authenticated session, never from the request. If your token endpoint accepted something like req.body.userId, anyone could request a valid token for another issuer and open their verification. Bluprynt can't detect this because the token would be correctly signed.

Not using Node.js?

Generate the JWT with any library for your language. Sign it with HS256 using your SECRET_KEY, and include these claims:

{
  "sub": "user-123",          // your internal user ID
  "iss": "your-partner-id",   // your partner ID
  "iat": 1766146154,          // issued at (Unix seconds)
  "exp": 1766149754           // expires at (Unix seconds)
}

For example, in Python with PyJWT:

import time, jwt

now = int(time.time())
access_token = jwt.encode(
    {"sub": user.id, "iss": "your-partner-id", "iat": now, "exp": now + 3600},
    BLUPRYNT_SECRET_KEY,
    algorithm="HS256",
)

4. Open the widget on your frontend

import { kyi } from '@bluprynt/kyi-widget-sdk'

const { accessToken } = await fetch('/api/kyi/token', { method: 'POST' })
  .then((r) => r.json())

const widget = kyi('modal', 'kyi', accessToken, {
  onReady: () => console.log('Widget loaded'),
  onClose: () => console.log('Widget closed'),
  onError: (error) => console.error(error),
})

Generate a new token each time you open the widget rather than caching one. Tokens are short-lived on purpose.

Display modes

In both modes the widget closes when the issuer clicks the close button, clicks outside it, or presses Escape.

Scopes

The scope decides which screen the widget opens on.

ScopeOpensUse it for
kyiThe verification flowStarting or continuing KYB and wallet verification.
asset-listThe issuer's assetsLetting issuers review what they've verified.
wallet-listThe issuer's walletsLetting issuers review their verified wallets.

Cleaning up

The widget removes itself when the issuer closes it. If you need to close it from your own code, for example when the user navigates away in a single-page app, call widget.destroy().

React example

import { useEffect, useRef } from 'react'
import { kyi, type KYIWidget } from '@bluprynt/kyi-widget-sdk'

export function VerifyButton() {
  const widgetRef = useRef<KYIWidget | null>(null)

  useEffect(() => () => widgetRef.current?.destroy(), [])

  const open = async () => {
    const { accessToken } = await fetch('/api/kyi/token', { method: 'POST' })
      .then((r) => r.json())
    widgetRef.current = kyi('modal', 'kyi', accessToken, {
      onClose: () => { widgetRef.current = null },
    })
  }

  return <button onClick={open}>Verify your asset</button>
}

Security checklist

  • Your SECRET_KEY lives only on your server.
  • Every origin that embeds the widget is on your allowlist with Bluprynt.
  • Your token endpoint requires login and takes the user ID from the session.
  • User IDs are stable, unique and never reused.
  • Tokens are short-lived and generated fresh for each widget session.
